# Security Policy

OpenOfficeLLM runs a local HTTPS service on `127.0.0.1` that brokers model
calls, stores provider API keys, and serves the Office task pane and Chrome
extension. That makes its security surface unusual for a "local app", so this
policy is explicit about the trust model.

## Scope

In scope:

- The host service (`packages/host`) — TLS bootstrap, origin/token auth, DPAPI
  secret storage, static file serving, provider brokering, MCP client.
- The Chrome extension pairing flow (`packages/host/src/pairing.ts`,
  `packages/extension/src/browser/pairing.ts`).
- The Office add-in manifest generation and registration.

Out of scope:

- The throwaway Phase 0 spike in `/spike`. It is a regression check, not a
  shipped surface.
- Upstream model providers (Ollama, LM Studio, Anthropic, OpenAI, etc.). A
  vulnerability in a provider is reported to that vendor.

## Trust model

| Boundary                 | Control                                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| Webview → host service   | Origin allowlist + per-launch bearer token injected into the served HTML                                                              |
| Extension → host service | Origin allowlist (paired extension ids, exact match, no wildcards) + token; `X-OpenOfficeLLM-Extension` CSRF signal                   |
| Host service → API keys  | Windows DPAPI (`CurrentUser` scope); never serialized to any webview; no endpoint returns a secret value                              |
| Host service → document  | Only via edits the pane requests; the service never touches Office directly                                                           |
| Local CA                 | Generated by the host, trusted into `Cert:\CurrentUser\Root` on Windows / login keychain on macOS. Removed by thumbprint on uninstall |

What this **does not** protect against:

- An attacker with code execution on the machine is already past every
  boundary here. DPAPI `CurrentUser` scope protects against other users on
  the same machine, not against malware running as you.
- The host binds loopback only. A machine that forwards loopback to the
  network (e.g. a misconfigured SSH tunnel) voids the origin assumption.

## Reporting a vulnerability

**Please do not file public GitHub issues for security reports.**

Use GitHub's **private vulnerability reporting** on the repository
(Security → Report a vulnerability). Include:

1. A description of the issue and its impact.
2. Steps to reproduce, including the host/OS and Office build if relevant.
3. Any proof-of-concept code or output.

Please do not publish the issue until a fix is released.

## Disclosure

Once a fix is released, the vulnerability is documented in the release notes
with credit to the reporter (unless you prefer to remain anonymous).
